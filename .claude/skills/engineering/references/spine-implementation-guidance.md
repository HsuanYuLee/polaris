# 新脊椎施作端指引

這份是施作端動手前讀的東西。它描述這條流程怎麼運作，讀完你會知道自己站在哪裡、
手上有什麼、以及什麼時候該把事情交出去。

## 一個 source 長什麼樣

一個 source 是**一個凍結塊加一份活文件**。

凍結塊是斷言：這件事成功的定義。它在正文的 fence 之間，人看得見、簽得下去，封條
（`assertions_hash` / `frozen_by` / `frozen_at`）放在 frontmatter。封條算的是 fence 內文，
所以寫封條本身不會讓它失效。`.claude/skills/engineering/scripts/frozen-assertion-fence.sh verify` 隨時可以重算比對。

活文件是其餘一切：現況、想法、試過什麼、撞到什麼、下一步。所有階段都寫它，它就是這個
source 的記憶。跨 session 接手時，凍結塊加活文件就是全部所需——一個新 session 讀完這兩個
檔案能繼續做事，不需要去翻別的 artifact。

這個形狀帶來的成本地板很低：一個只有一行斷言的工作，走完流程被迫產生的檔案不超過兩個
（活文件與 code）；純文件類的工作只有一個。`.claude/skills/engineering/scripts/check-spine-cost-floor.sh` 會把這件事
量出來。

## 兩個閘，中間什麼都沒有

流程只有兩個地方會擋你：

1. **定案結束時凍結斷言**（寫一次）。
2. **審查時執行 oracle**（判一次）。

中間是 loop。派工怎麼切、實作怎麼做、試幾次、走哪條路，都在 loop 裡，沒有第三個閘在等你
交表格。正因為兩個閘在，其餘一切才可以很隨便。

## oracle 分兩層

斷言承載意圖，鎖死；量測是斷言的代理，放開。

量測命令可以在 loop 內換——第一次寫的命令量不到目標是常態。換的時候帶上三元組：舊命令的
hash、新命令的 hash、以及**這條新命令在實作之前紅過**的證據，交給
`.claude/skills/engineering/scripts/record-measurement-change.sh record`。紅不了的命令什麼都沒量；一個因為工具不存在
而失敗的紀錄不算紅過，它只證明環境壞了。

量測命令跑起來時走 `.claude/skills/engineering/scripts/run-hardened-oracle.sh`。它會把宣告的工具先探一次能力再釘住，
要求命令產出證明自己量到東西的輸出，並原樣保留 stderr 與 exit code。這是因為工具會說謊：
PATH 上較早的 shim、靜默跳過的測試、被吞成 generic timeout 的錯誤，三者都能讓一個空的
執行看起來像綠的。

## 四類流轉，只有一類停人

做到一半發現不對時，看是哪一類：

| 發現的問題 | 往哪走 |
|---|---|
| 量測方法不對（命令量錯東西） | 原地改，帶紅過證據換命令，繼續 |
| 切分不對（這張單的邊界劃錯） | 回派工重切，繼續 |
| 斷言不對（成功的定義錯了） | 停，人類重簽 fence |

第三類是唯一停人的。前兩類自己轉完就往下走，不用等人回話。

停人的時候要**停得讓人看得見**。`spine-loop-state.sh stop --kind` 只認四種：
`assertion_wrong`（就是上表第三類）、`surfaced_concern`（下面那三件要浮出來的事）、
`unconverged_cap`（上限打到，`record` 自己會判，不用手動）、`unauthorized_action`
（需要人授權的不可逆動作）。其餘字串會被拒絕。

這四種以外的「停」都不是停，是不知道自己在哪——那個從
`spine-loop-state.sh where` 讀，不從人身上問。

施工計劃那一類不存在：這條流程不分「明確施工」與「嘗試實作」兩種模式。看得懂就做，看不懂
就先探。模式宣告是一個還沒被驗證的預測，用一次廉價的嘗試去測，比用一個昂貴的宣告去猜誠實。

## 一輪沒產出 code 也是一輪

「試過 A 路線，撞到 X，結論走 B，code 全丟」是這條流程的正常結果。這一輪的產出是知識，
把它寫進活文件就是交付。不需要為了讓這一輪看起來有東西，把失敗的探索包裝成交付。

輪次仍然前進，上限仍然存在（`.claude/skills/engineering/scripts/spine-loop-state.sh`，起始 N=3）。沒收斂的一輪就是
沒收斂，不論它產出什麼；連續沒收斂到上限時，流程會升人類而不是繼續自轉。上限是活區可調的
參數，不是驗收條件。

## 方法自由，以及它的三項邊界

怎麼做由你決定。用什麼寫法、拆幾個函式、先寫測試還是先寫實作，這些都不需要問。

有三件事 oracle 照不到，即使做了會變綠也要浮出來讓人看見：

- **新增依賴**：把一個新套件拉進來。
- **重造既有組件**：手寫一個 repo 裡已經有的東西。
- **擴大 security surface**：多開一個對外介面、多讀一份憑證、多信任一個輸入。

這三類的共同點是後果落在綠燈之外——測試會過，代價在別的地方。浮出來的方式是寫進活文件並
講清楚為什麼，等人回話再往下。

## 交出去的時候

活文件寫到讓下一個人（可能是明天的你）能接手：現在在哪、試過什麼、為什麼走這條、下一步是
什麼。凍結塊不要動——需要動它時，那是第四類流轉。
